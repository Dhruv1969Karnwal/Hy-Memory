## gnhf Behavior

Explored `/root/workspace-agent-server/gnhf` (TypeScript CLI, "good night, have fun").

### Iteration orchestration (`src/core/orchestrator.ts`)

1. An iteration runs the agent via `this.agent.run(prompt, cwd, {...})`.
2. On success (`result.output.success === true`) → `recordSuccess()` → `commitAll(message, cwd)`;
   on failure / abort / rate-limit / `PermanentAgentError` → `resetHard(cwd)` is called
   (unless a commit failure is already pending, in which case the dirty tree is kept for repair).
3. `commitAll` (`src/core/git.ts:238`) runs `git add -A`, then `git diff --cached --quiet`
   (no-op when nothing is staged), then `git -c commit.gpgsign=false -c tag.gpgsign=false commit -m <message>`.
   A commit failure is surfaced as `CommitFailedError`, which produces a "commit repair" prompt
   (`buildCommitFailurePrompt`) instead of a reset, so failed work is left in the tree for the next iteration.
4. `resetHard` (`src/core/git.ts:293`) = `git reset --hard HEAD` + `git clean -fd`, i.e. a failed
   iteration leaves no residue on the branch. Therefore each successful iteration must be
   self-contained and independently green.
5. `getBranchCommitCount` / `state.commitCount` track commits since `runInfo.baseCommit`;
   limits (`RunLimits`) enforce `--max-iterations`, `--max-tokens`, `--max-rate-limit-wait`.
6. `--stop-when <condition>` is evaluated after the commit-failure repair path; the orchestrator
   ends the run when the agent reports that condition.
7. Runtime-only flags (`--max-iterations`, `--max-tokens`, `--max-rate-limit-wait`, `--stop-when`)
   are never persisted to config (`AGENTS.md` invariant); `--stop-when` is persisted per-run for resume.

### Flags in play for this task

- `--current-branch` (`src/cli.ts:646`) — "Run on the current branch instead of creating a gnhf branch".
  Mutually exclusive with `--worktree` (`cli.ts:805` errors on the combination). This is why commits
  land directly on `chore/translate-chinese-to-english`.
- `--push` (`src/cli.ts:651`) — "Push the current branch after each successful iteration";
  only invoked when `record.success && limits.push` (`orchestrator.ts:693`) → `pushCurrentBranch`
  → `git push -u origin HEAD` (`git.ts:290`). A push failure aborts the run with an abortReason.
- `--max-iterations <n>` — abort after N total iterations (counts failures too).
- `--max-tokens <n>` — abort after N total input+output+cache tokens.
- `--stop-when <condition>` — end when the agent reports this condition.

### Commit message convention (`src/core/commit-message.ts`)

- With the `conventional` preset (configured via `commitMessage`): `"<type>(<scope>): <summary>"`,
  where `type ∈ build|ci|docs|feat|fix|perf|refactor|test|chore` (defaults to `chore` when the agent
  omits/invalidates it) and `scope` is optional and rendered as `(<scope>)`. The header is collapsed
  to a single line (`collapseHeader` collapses whitespace).
- Without the preset: `"gnhf <iteration>: <summary>"`.
- No co-author trailers are auto-added (`gnhf/AGENTS.md` convention).
- This task pins messages explicitly as `chore(i18n): <action>` per the checkpoint plan, which matches
  the conventional convention gnhf emits.

## Translation Policy Actually Applied

Two kinds of Chinese were found and treated differently:

1. **Prose** — docstrings, comments, prompts, log and error messages, UI copy, CLI output,
   test fixtures and their assertions. Translated to idiomatic English; test expectations were
   moved to the English wording in the same commit as the string they check.
2. **Load-bearing Chinese** — bytes that a matcher, a lexer, a protocol or a fixture compares
   against data outside the source tree. These stay the same bytes at runtime and are written as
   `\uXXXX` escapes with an English gloss comment, so the file is ASCII while the value is
   unchanged. Examples: CJK character classes and segmentation regexes
   (`memhub/apps/core/src/one_memory/retrieval/query_plan.py`, `hy_memory/**` tokenizers), SQL
   `LIKE` lexicons and receipt/protocol strings in Core, the SDK prompt needles in
   `memhub/apps/core/src/one_memory/hy_memory_bridge.py`, the escaped CJK class in
   `memhub/apps/core/tests/test_memory_qa.py`, and the one place a design doc quotes a rendering
   the code still emits in Chinese (`docs/multi_speaker_design.md`).

Identifiers, file and module names (`prompts_zh.py` stays), public APIs, signatures, env vars,
config keys, DB columns, CLI flags, HTTP routes, import paths, model names and SQL identifiers were
never touched. The only added file is this one; the only deleted file is `README.zh.md`.

## Mechanical Equivalence Harness

`/tmp/cora/` (outside the repo) holds the harness that produced and audited the change:

- `apply_strict.py` — the only way records reached the tree: refuses a record unless the target line
  held CJK, the replacement holds none, indentation matches, `{}` placeholder and escape-token
  multisets match, `"""` counts match, and the file's AST skeleton is unchanged.
- `escape_cjk.py` / `escape_regex.py` — convert load-bearing Chinese to escapes; the latter proves
  equivalence by comparing `sre_parse` trees.
- `py_guard.py` — snapshot/verify wrapper for the re-wrap pass (string-multiset + AST equality, no
  CJK, no E501, `ruff format` clean).
- `verify_code_token_identity.py` — tokenises base and branch, hides comments, collapses string
  literals to their prefix class and drops layout tokens: proves no identifier, keyword, operator or
  number moved. Reports the four register entries above and nothing else.
- `verify_text_only.py` — for docs and config: identical line count and every changed line contained
  CJK in the base revision.
- `tok_equiv.py` — token-level equivalence for the two files this interpreter (3.10) cannot parse.
